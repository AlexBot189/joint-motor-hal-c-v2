## 1. 系统定位

`stark_periph_manager_node` 是外骨骼机器人 RV1126B 平台上的外设管理进程，负责：

- CAN FD 总线上的关节电机通信（PDO 实时控制 + SDO 参数配置）
- 传感器数据聚合（IMU + 霍尔 + 力矩 + 气压计）
- 与算法进程的实时数据交换（共享内存）
- 安全监控与故障保护
- 物理按键交互和状态指示

节点位于算法进程和电机驱动板之间的中间层，屏蔽硬件细节，提供标准化的控制和数据接口。

```
┌─────────────────────────────────────────────────────────┐
│                 算法进程 (外骨骼步态控制)                  │
│  - 读 SHM: 双电机位置/速度/电流 + IMU 姿态 + 传感器数据      │
│  - 写 SHM: 控制命令 (扭矩/位置/速度/MIT) + 心跳            │
│  - 通过 stark_client.h API 访问, 无 HAL 依赖         │
```

## 2. 核心设计原则

### 2.1 观察者模式解耦

继承自 petrobot_periph_manager 的 Observer 模式，CanDispatcher 实现 `IMsgInternalDispatcher` 接口：

```
CanDispatcher (CAN协议解析)
    │
    ├── NotifyObserver(type, data)
    │       │
    │       ├──→ RosAdapter  (type=ROS)   → ROS Topic/Service
    │       └──→ WebAdapter  (type=WEB)   → WebSocket Push
    │
    └── 直接 SHM 写入 (反馈路径, 不走Observer)
            fb_buffer → 算法进程读取
```

- Dispatcher 只负责协议解析和数据分发，不处理业务逻辑
- Observer 各自独立，新增 Observer 不影响现有逻辑
- 使用 `boost::any` 传递数据，运行时类型判断

### 2.2 RT 与非 RT 分离

- **RT 路径**: 控制命令下发 (PDO)、反馈数据收集、安全监控
  - 禁止阻塞调用 (无 SDO、无 malloc、无 sleep)
  - 只用无锁数据结构 (SHM atomic、ring buffer)
  - 绑定 CPU 核心，SCHED_FIFO 调度

- **非 RT 路径**: 电机启动 (SDO)、校准 (SDO)、状态机、ROS、Web
  - 允许阻塞和 SDO 通信
  - SCHED_OTHER 调度

### 2.3 共享内存单写多读

- 反馈数据: motor_node 写，算法/Web 读，双 Buffer 防撕裂
- 控制命令: 算法写，motor_node 读，环形缓冲 SPSC 无锁
- 状态数据: motor_node 写，算法只读，atomic 保证可见性

### 2.4 故障隔离

- 电机 HAL 层内部异常不会传播到应用层
- CAN 断线重连由 HAL 自动处理
- 校准超时有明确的超时退出机制
- SHM 操作失败不影响进程存活

## 4. 状态机

```
        ┌──────────┐
        │ BOOTING  │  CANFD 初始化 + 等待电机上线
        └────┬─────┘
             │ 电机全在线 (或 5s 超时降级)
             ▼
        ┌──────────┐
   ┌───→│  READY   │  等待校准触发 (按键/首次启动跳过)
   │    └────┬─────┘
   │         │ 校准完成 / 首次启动跳过
   │         ▼
   │    ┌──────────┐
   │    │ RUNNING  │  RT 线程全速运行，周期上报
   │    └────┬─────┘
   │         │ 校准请求 (按键 3 连击)
   │         │ (停 RT → 回 READY → 执行校准 → 完成回 RUNNING)
   │         │ 取消请求 (按键 3 连击)
   │         │ (停 RT → 关透传 → 失能 → 回 READY)
   └─────────┘
        ┌──────────┐
        │  FAULT   │  异常状态 (当前未使用，预留)
        └──────────┘
```

### 4.1 校准流程

校准在 READY 状态中执行（状态机线程，非 RT），流程如下：

```
Step 1: Shutdown  (SDO 写 0x6040=0x06) → 等待 50ms
Step 2: 机械零位  (SDO 写 0x2531 sub=0, value=1) → 等待 20ms
Step 2.5: 力矩传感器零漂标定 (SDO 写 0x2531 sub=2, 调用 motor_hal_torque_zero_calib())
         失败不中断流程，仅记录日志
Step 3: DS402 使能 (0x06 → 0x07 → 0x0F) → 等待抱闸释放 120ms
Step 4: 设置控制模式 (默认电流模式, SDO 写 0x6060)
Step 5: 启动传感器透传 (period_div=4, bus_format=3)
```

**关键设计点**：
- Step 2.5 在去使能状态下执行（力矩传感器零漂标定要求电机静止）
- 零漂标定失败不影响校准整体流程，仅输出 warning 日志
- 校准超时时间默认 10s（`calib.timeout_ms`），从 Step 1 开始计时
- 单电机配置（`motor_id_l=0`）时，仅标定一侧

**状态转换规则**：
- BOOTING → READY: 所有已注册电机在线 (或 5s 超时)
- READY → RUNNING: 首次启动跳过校准，或按键触发校准完成后
- RUNNING → READY: 按键触发校准 (CALIBRATE 或 CANCEL)
- 任意状态 → FAULT: 预留

## 5. 数据流

### 5.1 反馈数据流 (电机 → 算法, 200Hz)

```
CAN FD 帧到达
  │
  ├─ 0x300 (反馈帧) ──→ fb_cache[motor_id]
  │                       motor_feedback_t:
  │                         position, velocity, current_iq,
  │                         error_code, temperature, torque_nm,
  │                         mode_fb, status_byte
  │
  ├─ 0x680 (传感器透传) → sensor_cache[motor_id]
  │                         hall_adc0/1/2, force_raw, knee_hall,
  │                         key_landing, data_valid
  │
  ├─ 0x6B0 (SPI力矩)   → sensor_cache[motor_id]
  │                         spi_force_raw_s24, spi_valid, spi_error
  │
  └─ IMU (SPI/I2C)     → imu_data_t (9轴融合)
       │
  ├─ FootPressureSensor  → foot_pressure_data_t (双足 AD, 1000Hz 串口)
  │     │
  │     ▼
  │  串口读取线程 (SCHED_OTHER):
  │    open(/dev/ttyS7) + 460800/8N1
  │    阻塞 read → 帧解析 (_ParseFrame) → mutex 缓存
  │    每 1s 打印 FPS 统计
  │       │
  │       ▼
  │  RT 工作线程 (1KHz):
  │    m_foot_sensor->Read(&fp)       ← 读缓存
  │    fb->foot_pressure = fp         ← 每周期写 SHM (不降采样)
  │    d.foot_pressure = fp           ← PeriodicUploadData (5ms上报)
  │       │
  │       ▼
  │  算法: stark_foot_pressure(&c)    ← zero-copy 读 SHM
  │  Web:  WebSocket JSON push         ← 6 路 AD 值推送到浏览器曲线
  │  demo: ./demo_algo foot            ← 逐帧打印真实帧间隔
  │
       ▼
  RT 上报线程 (200Hz):
    ├─ motor_hal_get_feedback()  → 读 fb_cache
    ├─ motor_hal_get_sensor()    → 读 sensor_cache
    ├─ ImuHALSensor::Read()      → 读 IMU 融合数据
    │
    ├─ 组装 feedback_frame_t → 写 fb_buffer[active^1]
    ├─ 内存屏障 (wmb)
    ├─ active_idx = active^1  (原子切换)
    └─ 算法进程检测到 active_idx 变化 → 读 fb_buffer[active]
```

### 5.2 控制命令流 (算法 → 电机, 1KHz)

```
算法进程:
  stark_torque/multi/pp/pv/mit()  // stark_client.h inline API
    │
    ├─ _stark_mbox_begin()        // SPSC 环形缓冲 slot 分配
    ├─ 写入 mailbox.frames[slot].cmd[id-1]
    └─ _stark_mbox_commit()       // seq_write 原子递增
        │
        ▼ RT 控制线程 (1KHz):
  ProcessMailbox():
    r = seq_read, w = seq_write
    for slot in [r..w):
      cmd = mailbox.frames[slot]
      ├─ STARK_CMD_TORQUE  → motor_hal_multi_ctrl(mode=CURRENT)
      ├─ STARK_CMD_POS     → motor_hal_multi_ctrl(mode=CSP)
      ├─ STARK_CMD_MULTI   → 双电机一帧广播
      ├─ STARK_CMD_MIT     → 走 0x110 MIT 独立帧
      └─ STARK_CMD_SET_MODE → 切换 PDO 模式 (双发防丢帧)
    seq_read += count
```

### 5.3 管理命令流 (算法 → 电机, 独立通道)

```
算法进程:
  stark_enable/disbale/estop/recover/clear_fault(1)
    │
    ├─ 写入 shm->mgmt_cmd[0]
    └─ mgmt_seq[0] 原子递增
        │
        ▼ RT 工作线程 (每周期检查):
  ProcessMgmt():
    for i in [0..motor_count):
      if mgmt_seq[i] != mgmt_ack[i]:
        ├─ STARK_CMD_ENABLE → PDO enable
        ├─ STARK_CMD_DISABLE → PDO disable + 电流清零
        ├─ STARK_CMD_ESTOP  → PDO estop + 刹车抱死
        └─ ...
        mgmt_ack[i] = mgmt_seq[i]
```

## 8. 足底压力传感器

### 8.1 概述

两个足底压力片通过 MCU 汇总后，经单路 UART (`/dev/ttyS7`) 以 460800bps 主动上报至 RV1126B。每片 3 个压力传感器，共 6 路 AD 值（0~4095）。

| 参数 | 规格 |
|------|------|
| 传感器 | 2 片 × 3 传感器，共 6 路 AD |
| 通信 | UART `/dev/ttyS7`，460800/8N1 |
| 帧格式 | `F2 01 C0 FF EE 0C [12B 大端] F1`，固定 19 字节 |
| 上报模式 | MCU 主动推送，主站只收不发 |
| 集成方式 | FootPressureSensor 类，仿 ImuHALSensor 模式 |

### 8.2 软件架构

```
FootPressureSensor (stark_periph_node 内部)
  ├─ Init("/dev/ttyS7", 460800, 10)
  │   ├─ open() + tcsetattr() → 配置 8N1
  │   └─ 启动串口读取线程 (SCHED_OTHER)
  │
  ├─ _ReaderThread() 串口读取循环
  │   ├─ read() → 环形缓冲 (1KB) → _ParseFrame()
  │   ├─ 帧校验: 0xF2 帧头 / 0xF1 帧尾 / 帧长 19 / SRC=0x01
  │   ├─ 提取 6 × uint16 大端 AD → 写入缓存 (mutex)
  │   └─ 每秒 FPS 统计: [FootPressure] FPS=N L:xxx xxx xxx R:xxx xxx xxx
  │
  ├─ Read(foot_pressure_data_t*)  ← 非阻塞, 读 mutex 缓存
  └─ IsReady() / IsOnline()       ← 状态查询
```

### 8.3 SHM 数据

```c
typedef struct {
    uint16_t adc[3];         /* 前掌/足弓/后跟, 0~4095 */
} foot_pad_t;

typedef struct {
    foot_pad_t  left;        /* 左脚 */
    foot_pad_t  right;       /* 右脚 */
    uint32_t    update_cycle;/* RT 周期号 */
    uint64_t    timestamp_us;/* 串口收帧时刻 (CLOCK_MONOTONIC) */
} foot_pressure_data_t;
```

位置: `feedback_frame_t` 尾部 + `PeriodicUploadData` 尾部，`_pad` 吸收新增字节，sizeof 不变。

### 8.4 数据路径

| 路径 | 频率 | 说明 |
|------|------|------|
| MCU → 串口 | 由 MCU 决定 | 主动上报，无请求 |
| 串口线程 → 缓存 | 每帧到达 | _ParseFrame 成功即更新 |
| RT → feedback_frame | 1ms (每周期) | 不降采样，demo_algo foot 逐帧消费 |
| RT → PeriodicUploadData | 5ms (report 周期) | demo_algo report + Web 曲线消费 |
| FPS 统计 | 每秒 | 日志打印实际帧率 |

### 8.5 调试接口

```bash
# 逐帧打印: 每条输出对应 MCU 真实一帧
./demo_algo foot

# 周期上报: 5ms 一次，含 FOOT 行
./demo_algo report

# Web 调试面板: 6 条足底压力曲线 (左绿/右黄)
http://<device>:8080
```

### 8.6 设计约束

1. 故障隔离: FootPressureSensor 初始化失败不影响电机状态机，SHM 字段全零
2. 不建独立 HAL 库: 串口协议简单，直接类封装
3. SHM 尾部追加: 不动任何现有字段偏移
4. 串口线程非 RT: 阻塞 I/O 不污染 RT 路径

## 9. 编译与部署

### 编译

```bash
# 使用 build.sh 交叉编译
./build.sh

# 关键 cmake 选项
-DENABLE_ROS=OFF       # ROS 适配器 (调试用)
-DENABLE_WEBSERVER=ON  # Web 调试面板
```

### 依赖

| 库 | 用途 |
|----|------|
| motor_hal (C) | CAN FD 驱动 + CANopen 协议栈 |
| imu_hal (C) | ICM45608 SPI/I2C + EMD-GAF 融合 |
| log_helper | spdlog 异步日志 |
| libgpiod | GPIO 按键监测 |
| pthread + rt | Linux RT 调度 |
| crow (header-only) | WebSocket 服务器 (可选) |

### 部署

```bash
# 拷贝到设备
scp stark_periph_manager_node root@device:/data/stark/bin/
scp stark_config.json root@device:/data/config/stark/

# RT 环境初始化
./setup_rt_env.sh
# 或手动:
# echo -1 > /proc/sys/kernel/sched_rt_runtime_us
# ulimit -l unlimited

# 启动
/data/stark/bin/stark_periph_manager_node -c /data/config/stark/stark_config.json

# 查看日志
journalctl -u stark_node -f
```

## 11. 关键约束

1. **SHM 64KB 单页**: 所有数据必须在 64KB 内，新增字段注意 padding 对齐
2. **RT 线程零阻塞**: 控制/上报/安全线程禁止任何阻塞调用
3. **单进程**: 不支持多实例，SHM 名称 `/stark_shm` 固定
4. **CAN FD BRS 必须**: 数据段 5Mbps，不支持 Classical CAN
5. **电机 ID 固定**: 1=右髋, 2=左髋，不可运行时变更
6. **root 权限**: SHM 创建 + RT 调度 + CAN 接口都需要 root
