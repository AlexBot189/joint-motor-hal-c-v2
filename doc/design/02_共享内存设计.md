## 1. 概述

共享内存 (`/dev/shm/stark_shm`) 是 `stark_periph_manager_node` 和算法进程之间的唯一数据交换通道。设计目标：

- **零拷贝**: 算法进程通过 `stark_client.h` 直接读取 SHM，无需 IPC 开销
- **单写多读**: 每个数据区域只有一个写入方，避免锁竞争
- **无锁并发**: 使用原子操作 + 双缓冲 + 环形缓冲实现 lock-free
- **64KB 固定**: 单页大小，确保一次 mmap 即可完成映射

## 3. 双 Buffer 反馈区

### 3.1 设计原理

反馈数据由 motor_node RT 线程写入，算法进程和 Web 调试面板读取。多读者单写者场景，使用双 Buffer 实现无锁并发：

```
写入方 (RT线程):
  1. 组装新一帧 feedback_frame_t
  2. 写入 fb_buffer[active ^ 1]   ← 写入备用区
  3. write memory barrier (sfence)
  4. active_idx = active ^ 1      ← 原子切换

读取方 (算法/Web):
  1. idx = atomic_load(active_idx, acquire)
  2. 读 fb_buffer[idx]            ← 读激活区
  3. 读取过程中写入方不会修改此区域 (因为写的是另一个)
```

### 3.2 feedback_frame_t 结构

```c
typedef struct {
    motor_data_t      motor[2];           // [0]=右(ID=1), [1]=左(ID=2)
    stark_sensor_data_t sensor[2];        // 传感器透传
    imu_data_t        imu;                // IMU 9轴融合
    barometer_data_t  baro;               // 气压计 (预留)

    // 端到端延迟追踪 (μs)
    uint64_t ts_can_rx;                   // CAN帧到达
    uint64_t ts_cache_write;              // 缓存写入
    uint64_t ts_shm_read;                 // RT线程读缓存
    uint64_t ts_shm_write;                // SHM写入
    uint64_t ts_algo_read;                // 算法读SHM
    uint64_t ts_algo_done;                // 算法计算完成
    uint64_t ts_mailbox_read;             // RT读mailbox
    uint64_t ts_pdo_sent;                 // PDO发送

    uint64_t timestamp_us;                // 组装时刻
    uint8_t  _pad[4];
} feedback_frame_t;
```

### 3.3 motor_data_t

```c
typedef struct {
    int16_t  position;          // 编码器角度 cnt, [-32768,32767]→[-180°,180°]
    int16_t  velocity;          // 转速 RPM
    int16_t  current_iq;        // Q轴电流 mA
    int16_t  temperature;       // 温度 0.1°C
    uint8_t  status_byte;       // bit7=使能 bit6=抱闸 bit5=错误 bit4=到位
    uint8_t  mode;              // 控制模式 (0x1-0x7)
    uint8_t  error_code;        // 故障码
    uint8_t  _pad;
    // V2 新增:
    int16_t  torque_nm;         // 力矩反馈 0.05N.m
    uint8_t  mode_fb;           // 模式反馈 bit3:0
    uint8_t  _pad2[1];
} motor_data_t;
```

### 3.4 读取约定

- 算法侧通过 `stark_fb(&c, id)` 读取，内部处理 `active_idx`
- 读操作零拷贝，不持有锁
- 不要在读取期间长时间 hold 指针 (写入方可能在下个周期切换 Buffer)

## 4. Mailbox 环形缓冲 (控制命令)

### 4.1 设计原理

邮箱采用 SPSC (Single Producer, Single Consumer) 环形缓冲：

```
        算法 (Producer)                    RT线程 (Consumer)
        ────────────                       ────────────
        slot = seq_write % DEPTH           r = seq_read
        write frame[slot]                  w = seq_write
        seq_write++                        消费 slot [r..w)
                                           seq_read += count
```

- 深度 8，算法 1KHz 写入，RT 1KHz 消费，理论上不会满
- 算法写入如果追上 RT 消费 (写游标 - 读游标 > 8)，`_stark_mbox_begin()` 返回 -1
- 写入方独占 `seq_write`，读取方独占 `seq_read`，无 CAS 竞争

### 4.2 mailbox_frame_t

```c
typedef struct {
    motor_command_t cmd[STARK_MAX_MOTORS];  // 每电机独立命令
} mailbox_frame_t;

typedef struct {
    uint8_t  motor_id;          // 1=右, 2=左
    uint8_t  cmd;               // stark_cmd_type_t
    int32_t  value;             // target1
    int32_t  value2;            // target2
    int32_t  feedforward;       // 前馈

    // MIT 专用 (12bit 跨字节编码)
    uint16_t mit_pos;           // 目标位置 [0-65535]
    uint16_t mit_vel;           // 目标速度 [0-4095]
    uint16_t mit_kp;            // 位置增益 [0-4095]→[0-500]
    uint16_t mit_kd;            // 速度增益 [0-4095]→[0-5]
    uint16_t mit_torque;        // 目标力矩 [0-4095]

    uint64_t timestamp_us;      // 算法下发时刻
} motor_command_t;
```

## 5. 管理命令通道

管理命令 (enable/disable/estop/recover/clear_fault) 走独立 slot，不和算法 mailbox 竞争。

```c
// 每电机一个 slot
volatile uint8_t mgmt_cmd[2];    // stark_cmd_type_t, 0=idle
volatile uint8_t mgmt_seq[2];    // 写入递增
volatile uint8_t mgmt_ack[2];    // RT 确认 (拷贝 seq)
```

**协议**：
1. 算法写入 `cmd` 值
2. 内存屏障
3. `mgmt_seq[i]` 原子递增
4. RT 线程检测 `seq != ack`，执行命令
5. RT 执行完毕：`mgmt_ack[i] = mgmt_seq[i]`

每电机独立 slot，互不覆盖。多电机命令并发写入，RT 逐个处理。

## 6. SDO 控制通道

SDO 命令 (非 RT) 也走独立 slot：

```c
typedef struct {
    uint8_t  motor_id;
    uint8_t  cmd;            // STARK_CMD_SDO_CUR/POS/VEL
    int32_t  value;          // 主值
    int32_t  value2;         // 副值 (加速)
    int32_t  feedforward;    // 前馈 (速度)
} sdo_cmd_slot_t;

sdo_cmd_slot_t sdo_cmds[2];         // 每电机一槽
volatile uint8_t sdo_seq[2];       // 算法递增
volatile uint8_t sdo_ack[2];       // 主循环处理完拷贝
```

**协议**: 同管理命令，但由主循环 (非 RT) 消费，调用 `StarkMotorCtrl` 的 SDO 方法。

## 7. 周期上报区

`PeriodicUploadData` 是 IMU + 双电机 + 传感器的统一上报结构，~128 字节。

```c
typedef struct {
    // IMU 段
    float gyro_dps_x/y/z, quat_w/x/y/z, gyro_roll/pitch/yaw;
    float acc_x/y/z, air_pressure;

    // 右电机 (ID=1)
    int32_t  RealtimeVelocity;       // RPM×10
    int16_t  motor_abs_angle;        // °×10
    int16_t  cal_Iq_current;         // A×100
    int32_t  motor_temp;             // °C×100
    int16_t  fault_code, motor_state;
    uint16_t hall_a/b/c_data;
    uint16_t df181_torque;
    int16_t  knee_hall;
    uint8_t  key_landing, torque_valid;
    float    spi_torque;
    uint8_t  spi_valid, spi_error;

    // 左电机 (ID=2) — 同上
    ..._left;

    // 帧同步
    uint32_t timestamp_ms;           // CLOCK_REALTIME
    uint32_t frame_cycle;            // RT周期号
    uint32_t motor_ts_us;            // 0x300 CAN到达时刻
    uint32_t imu_ts_us;              // IMU融合时刻
    uint32_t sensor_ts_us;           // 0x680 CAN到达时刻
} PeriodicUploadData;
```

**读取方式**：
- 轮询: `stark_report_try_read(&c, &ver, &d)` — 版本号比较
- 阻塞: `stark_report_wait(&c, &ver, &d, timeout_ms)` — futex 等待

## 8. 心跳机制

```c
volatile uint32_t algo_heartbeat;           // 算法递增
uint32_t          algo_heartbeat_timeout_ms; // 超时阈值
volatile uint32_t rt_cycle;                 // RT递增
```

- `algo_heartbeat`: 算法每 200ms 调用 `stark_heartbeat()` 递增
- `rt_cycle`: RT 线程每周期递增 (1KHz)
- `algo_heartbeat_timeout_ms`: 由 stark_node 启动时写入

双向检测：
- 算法检测 `rt_cycle` 变化 → 判断 stark_node 存活
- stark_node 检测 `algo_heartbeat` 变化 → 判断算法存活

## 9. 并发安全保证

| 区域 | 写入方 | 读取方 | 同步机制 |
|------|--------|--------|----------|
| fb_buffer | RT线程 | 算法/Web | 双Buffer + active_idx (release/acquire) |
| mailbox | 算法 | RT线程 | SPSC环形缓冲 + seq原子 (relaxed) |
| mgmt_cmd | 算法 | RT线程 | seq/ack协议 + fence |
| sdo_cmds | 算法 | 主循环 | seq/ack协议 + fence |
| periodic_data | RT线程 | 算法/Web | version + atomic |
| 状态字段 | motor_node | 算法 | atomic store/load |
| algo_heartbeat | 算法 | motor_node | atomic add/load |
| rt_cycle | RT线程 | 算法 | atomic store/load |

无锁设计的关键：每个字段只有一个写入方，不需要 `compare_exchange`。

## 10. 使用示例 (算法侧)

```c
#include "stark_client.h"

int main() {
    stark_client_t c;

    // 等待 stark_node 启动
    while (stark_open(&c) != 0) usleep(100000);

    // 等待校准完成
    while (!stark_ready(&c)) usleep(100000);

    // 使能并切电流模式
    stark_enable(&c, 1);
    stark_enable(&c, 2);
    stark_set_mode(&c, 1, STARK_MODE_CURRENT);
    stark_set_mode(&c, 2, STARK_MODE_CURRENT);
    usleep(5000);

    // 控制循环 1KHz
    uint32_t rpt_ver = 0, rt_cycle = 0;
    while (1) {
        // 读反馈
        motor_data_t m1 = stark_fb(&c, 1);
        motor_data_t m2 = stark_fb(&c, 2);
        imu_data_t  imu = stark_imu(&c);

        // 步态算法 → 力矩
        int32_t torque_r = gait_control(m1, m2, imu);

        // 写控制命令
        stark_torque(&c, 1, torque_r);
        stark_torque(&c, 2, -torque_r);

        usleep(1000);

        // 关注上报数据
        const PeriodicUploadData* d;
        if (stark_report_try_read(&c, &rpt_ver, &d)) {
            // d->hall_a_data, d->df181_torque, d->spi_torque...
        }

        // 心跳 (每200ms)
        static int tick = 0;
        if (++tick % 200 == 0) {
            stark_heartbeat(&c);
            if (!stark_rt_alive(&c, &rt_cycle)) {
                // stark_node 挂了，等待恢复
                while (!stark_ready(&c)) usleep(100000);
                stark_enable(&c, 1); stark_enable(&c, 2);
                usleep(5000);
            }
        }
    }

    stark_estop(&c, 1);
    stark_estop(&c, 2);
    stark_close(&c);
    return 0;
}
```

## 11. 内存对齐注意事项

- `feedback_frame_t` 和 `PeriodicUploadData` 中的 `float` 字段需要 4 字节对齐
- `timestamp_us` 和 `seq` 字段需要 8 字节对齐 (uint64_t)
- `_pad` 字段必须显式声明，确保结构体尾部对齐
- SHM 总大小必须保持 64KB，新增字段从 `_pad` 中分配
- 所有多字节字段使用主机字节序 (LE, ARM 小端)
