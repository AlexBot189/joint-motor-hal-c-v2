# IMU 带宽计算：I2C vs SPI

> ICM45608, mode=7 (800Hz raw / 50Hz GAF), RV1126B

---

## 1. 核心公式

```
传输时间 = 总线字节数 × 每字节耗时
每字节耗时 = 每字节时钟数 ÷ 总线频率
```

| 总线 | 频率 | 每字节时钟 | 每字节耗时 |
|------|------|-----------|-----------|
| I2C | 400 KHz | 9 (8数据 + 1 ACK) | **22.5 μs** |
| SPI | 10 MHz | 8 (纯数据) | **0.8 μs** |

---

## 2. 一次读取的结构（以 I2C 为例）

每次从 IMU 读数据，I2C 总线上分两段：

```
┌─ 写段：告诉芯片"我要读哪个寄存器" ────────────────────────┐
│ START + 设备地址(W) + ACK + 寄存器地址 + ACK               │   ~4 字节
└──────────────────────────────────────────────────────────┘

┌─ 读段：芯片把数据吐出来 ──────────────────────────────────┐
│ RESTART + 设备地址(R) + ACK + 数据[0] + ACK + ...          │
│ ... + 数据[N-1] + ACK + 数据[N] + NACK + STOP             │   N + 4 字节
└──────────────────────────────────────────────────────────┘
```

> **固定开销约 8 字节**，不管你读 1 字节还是 100 字节。

FIFO 读取需要两次 I2C 操作：
1. 读 FIFO_COUNT（2 字节）→ 先知道有多少数据
2. 读 FIFO_DATA（N 字节）→ 读实际数据

---

## 3. ICM45608 FIFO 每包大小

mode=7 配置：`accel(6B) + gyro(6B) + temp(1B) + timestamp(3B) + header(1B) = 17 字节`

| 周期类型 | 频率 | FIFO 内容 | 包大小 |
|---------|------|----------|--------|
| 普通周期 | 800Hz (15/16) | raw 数据 | **17 字节** |
| GAF 融合周期 | 50Hz (1/16) | raw + quat + mag + heading | **35 字节** |

---

## 4. I2C 400KHz 耗时

### 普通周期（17B 数据）

| 步骤 | 总线字节 | 耗时 |
|------|---------|------|
| 读 FIFO_COUNT（2B） | 8 + 2 = 10 | 225 μs |
| 读 FIFO_DATA（17B） | 8 + 17 = 25 | 563 μs |
| **合计** | **35** | **~788 μs** |

### GAF 融合周期（35B 数据）

| 步骤 | 总线字节 | 耗时 |
|------|---------|------|
| 读 FIFO_COUNT（2B） | 8 + 2 = 10 | 225 μs |
| 读 FIFO_DATA（35B） | 8 + 35 = 43 | 968 μs |
| **合计** | **53** | **~1193 μs** |

### 跟周期预算对比

```
周期预算: 1250 μs (800Hz)
────────────────────────────
普通周期:  788 μs  →  63%  ✅
融合周期: 1193 μs  →  95%  ⚠️
────────────────────────────
+ 隐藏开销 (中断延迟 ~50μs + 调度抖动 ~50μs):
融合周期: 1193 + 100 = 1293 μs  ❌ 超出预算
```

---

## 5. SPI 10MHz 耗时

SPI 没有 ACK，没有 START/STOP，只有 CS 选中 + 读写命令：

### 普通周期（17B 数据）

| 步骤 | 总线字节 | 耗时 |
|------|---------|------|
| 读 FIFO_COUNT | 2(命令) + 2(数据) = 4 | 3 μs |
| 读 FIFO_DATA | 2(命令) + 17 = 19 | 15 μs |
| **合计** | **23** | **~18 μs** |

### GAF 融合周期（35B 数据）

| 步骤 | 总线字节 | 耗时 |
|------|---------|------|
| 读 FIFO_COUNT | 2(命令) + 2(数据) = 4 | 3 μs |
| 读 FIFO_DATA | 2(命令) + 35 = 37 | 30 μs |
| **合计** | **41** | **~33 μs** |

### 跟周期预算对比

```
周期预算: 1250 μs (800Hz)
────────────────────────────
融合周期: 33 μs  →  2.6%  ✅ 余量巨大
```

---

## 6. 总结

| | I2C 400KHz | SPI 10MHz | 差值 |
|------|-----------|-----------|------|
| 每字节耗时 | 22.5 μs | 0.8 μs | **28×** |
| 普通周期 | 788 μs (63%) | 18 μs (1.4%) | **44×** |
| 融合周期 | 1193 μs (95%) | 33 μs (2.6%) | **36×** |
| 余量 | 57 μs (不够) | 1217 μs | — |
| Clock Stretching | 0~500μs 不可控 | 无 | — |

**结论**：400KHz I2C 在 800Hz mode 下勉强够用但没有安全余量，GAF 融合帧时已达 95% 占用，加上中断延迟和 clock stretching 可能溢出。SPI 从带宽和确定性上都远优于 I2C。

---

## 附：速算公式

```
I2C 耗时 ≈ (读数据字节数 + 18) × 22.5 μs    ← 含两次操作开销 + 8B 帧开销
SPI 耗时 ≈ (读数据字节数 +  4) ×  0.8 μs    ← 含两次命令开销
```

代入 mode=7 融合帧：
```
I2C: (35 + 18) × 22.5 = 1193 μs
SPI: (35 +  4) ×  0.8 =   31 μs
```
