## 1. CPU 占用分析

### 1.1 确认进程

```bash
# 系统整体 CPU
top

# 指定进程
top -p $(pidof stark_periph_manager_node)
```

### 1.2 展开线程定位

```bash
top -H -p $(pidof stark_periph_manager_node)
```

输出示例（本案例：足压串口 O_NONBLOCK 空转）：

```
PID   USER   PR  NI    VIRT    RES   %CPU  S  COMMAND
 695  root   20   0  236868 104372   0.0  S  stark_periph_ma   ← 主线程
 709  root   20   0  236868 104372   0.0  S  stark_periph_ma
 711  root  -86   0  236868 104372   2.0  S  stark_periph_ma   ← RT 线程, PR 负数
 827  root  -51   0  236868 104372   4.0  D  stark_periph_ma   ← RT, D=阻塞在 I/O
 828  root   20   0  236868 104372  99.9  R  stark_periph_ma   ← ❌ 问题线程
 829  root   20   0  236868 104372   0.0  S  stark_periph_ma
 830  root   20   0  236868 104372   2.7  S  stark_periph_ma

 835  root   20   0  236868 104372   2.0  S  stark_periph_ma
```

判断标准：

| 指标 | 正常 | 异常 |
|------|------|------|
| PR 负数 (RT) | CPU 可能高 (1KHz 循环) | — |
| PR=20 (普通) | CPU < 5% | CPU > 50% |
| S 状态 | S(睡眠) / D(阻塞 I/O) | **R(运行中)** |
| PR=20 + 99% CPU + R | — | **死循环确认** |

### 1.3 确认死循环

```bash
cat /proc/<TID>/status
```

本案例 PID 828 输出：

```
State:  R (running)                     ← 从未睡眠
voluntary_ctxt_switches:  0             ← 从未主动让出 CPU
nonvoluntary_ctxt_switches: 780800      ← 被强制切走 78 万次
wchan:  0                               ← 不在内核态阻塞
```

**`voluntary_ctxt_switches = 0`** — 线程没调过任何 `sleep/read/wait/select`，纯空转。

### 1.4 strace 抓系统调用

```bash
timeout 2 strace -p <TID> 2>&1 | head -20
```

本案例输出：

```
read(8, 0x7fabf23748, 256) = -1 EAGAIN (Resource temporarily unavailable)
read(8, 0x7fabf23748, 256) = -1 EAGAIN
read(8, 0x7fabf23748, 256) = -1 EAGAIN
... (无限重复)
```

`read(8, ..., 256)` + `EAGAIN` = 非阻塞读 fd=8，无数据，立刻重试。

### 1.5 确认设备

```bash
ls -l /proc/<PID>/fd/8
```

输出 `8 -> /dev/ttyS7` → 足压串口，代码 `tmp[256]` → `FootPressureSensor::_ReaderThread`。

### 1.6 定位源码

```c
// FootPressureSensor.cpp
m_fd = open(uart_dev, O_RDWR | O_NOCTTY | O_NONBLOCK);  // ← O_NONBLOCK
...
while (m_running) {
    n = read(m_fd, tmp, sizeof(tmp));      // ← strace 抓到这里
    if (n < 0 && errno == EAGAIN) continue; // ← 无 sleep, 空转
}
```

### 1.7 排查流程

```
top -H -p <PID>
       │
       ▼
PR=20 + CPU 99% + State=R  →  记下 TID
       │
       ▼
cat /proc/TID/status  →  voluntary_ctxt_switches=0 ?
       │ 是（死循环确认）
       ▼
timeout 2 strace -p TID  →  看死循环调哪个系统调用
       │

       │
       ▼
搜源码  →  定位代码行  →  修复
```

## 2. 常见死循环模式与修复

### 2.1 O_NONBLOCK + EAGAIN 无 sleep

```c
// 错误写法
m_fd = open(dev, O_RDWR | O_NONBLOCK);
while (running) {
    n = read(m_fd, buf, size);
    if (n < 0 && errno == EAGAIN) continue;  // 空转
}
```

**修复**：打开端口后清除 O_NONBLOCK。

```c
m_fd = open(dev, O_RDWR | O_NONBLOCK);   // 防止 DCD 未就绪卡死 open
tcsetattr(m_fd, ...);
fcntl(m_fd, F_SETFL, fcntl(m_fd, F_GETFL) & ~O_NONBLOCK);  // 恢复阻塞
// 后续 read() 正常阻塞，VTIME 超时生效
```

### 2.2 select/poll 超时 0

```c
struct timeval tv = {0, 0};           // 超时 0 → 立刻返回
select(fd+1, &rfds, NULL, NULL, &tv); // 等于没阻塞
```

**修复**：给合理超时值，如 `tv = {0, 20000}`（20ms）。

### 2.3 CAN socket 丢数据空转

```c
n = read(can_fd, &frame, sizeof(frame));
if (n <= 0) continue;
```

**修复**：用 `select`/`poll` 等待可读事件。

## 3. 内存 (DDR) 分析

### 3.1 总览

```bash
cat /proc/<PID>/status | grep -E "Vm|Rss|Threads|Name"
```

本案例输出：

```
Name:   stark_periph_ma
VmPeak:   261124 kB      # 虚拟内存峰值
VmSize:   236868 kB      # 虚拟内存当前
VmLck:    236856 kB      # 锁定内存 (mlockall)
VmRSS:    104372 kB      # 物理内存驻留集
RssAnon:   99064 kB      # 匿名页 (堆/栈)
RssFile:    5244 kB      # 文件映射 (.so/代码)
RssShmem:     64 kB      # 共享内存 (stark_shm)
VmData:    99048 kB      # 堆 + 静态数据
VmStk:       132 kB      # 主线程栈实际占用
VmExe:       668 kB      # 可执行文件大小
VmLib:      5140 kB      # 动态库占用
Threads:       13        # 线程数
```

### 3.2 确认 mlockall

```bash
grep -n "mlockall" src/motor/motor_rt_worker.cpp
```

输出：`977: if (mlockall(MCL_CURRENT | MCL_FUTURE) != 0)`

**`mlockall` 把进程全部虚拟内存物理锁定**，禁止换出，保证 RT 线程无缺页中断。代价是 RSS 几乎等于整个虚拟内存工作集。

### 3.3 内存组成分解

```bash
# 二进制段大小
size <binary>
```

本案例：

```
text      data     bss      dec      hex
1322369   17280    18408    1358057  14b8e9
```

| 来源 | 大小 | 说明 |
|------|------|------|
| text (代码) | 1.3MB | 可执行代码 |
| data (全局) | 17KB | 已初始化全局变量 |
| bss (零初始化) | 18KB | 未初始化全局变量 |
| 动态库 (.so) | 5MB | libmotor_hal.so, libimu_hal.so, liblog_helper.so, libgpiod.so |
| 13 个线程栈 (mlock 锁定) | ~13MB | 每线程默认虚拟 8MB，mlock 按实际接触页锁定 |
| 堆 (boost/crow/json) | ~84MB | header-only 模板膨胀 + 运行时对象 |
| SHM | 64KB | /dev/shm/stark_shm |
| **合计** | **~104MB** | |

### 3.4 为什么 10% DDR 是正常的

1. **`mlockall` 是 RT 系统的标配** — 电机 1KHz 循环不能有缺页中断，必须全锁
2. 线程多 (13) + mlock 锁死全部栈 → ~13MB 物理内存常驻
3. `boost` + `crow` + `nlohmann/json` 三个 header-only 库模板膨胀 → 大量堆对象
4. RSS = VSS 的关系：`VmLck(236MB) ≈ VmSize(236MB)` → mlock 把几乎所有虚拟内存锁成了物理内存

| 内存来源 | 不可缩减 | 可优化 |
|----------|:--:|:--:|
| RT mlockall | ✅ RT 必须 | — |
| 电机 CAN 驱动 | ✅ 核心功能 | — |
| IMU 驱动 | ✅ 核心功能 | — |
| 线程栈 × 13 | ✅ RT 多线程架构 | ⚠️ 减少线程数 |
| crow WebServer | — | ⚠️ 关 WEBSERVER 可缩减 ~10-20MB |
| nlohmann/json | — | ⚠️ 换轻量 JSON 库 |
| boost 头文件 | — | ⚠️ 部分替换为标准库 |

### 3.5 各区段详情

```bash
# 按内存区段看物理页分布（Rss 大的段要关注）
cat /proc/<PID>/smaps | awk '/^[0-9a-f]/{name=$NF; next} /^Rss:/{rss=$2} /^Pss:/{pss=$2; if(rss>0) printf "%8d kB  %s\n", rss, name}'
```

### 3.6 共享内存

```bash
ls -lh /dev/shm/stark_shm
```

正常：64KB，一个缓存页大小。

### 3.7 检查内存泄漏

```bash
# 间隔一段时间比较 RSS 变化
cat /proc/<PID>/status | grep VmRSS; sleep 60; cat /proc/<PID>/status | grep VmRSS

# 或持续监控
while true; do
    echo -n "$(date +%T) "
    cat /proc/<PID>/status | grep VmRSS
    sleep 10
done
```

RSS 稳定不增长 = 无泄漏。持续增长 = 有泄漏，需用 valgrind 或 heaptrack 排查。

## 4. 内存排查流程

```
cat /proc/PID/status | grep Vm
       │
       ▼
VmRSS > 预期？
       │ 是
       ▼
cat /proc/PID/status | grep VmLck
       │
       ▼
VmLck ≈ VmSize？→ mlockall → 正常，需评估是否可以减少锁定范围
       │
       ▼
size <binary> → 看代码/数据段
ls -lh /dev/shm/stark_shm → 看 SHM

查看各区段：
cat /proc/PID/smaps | awk '/^[0-9a-f]/{name=$NF;next} /^Rss:/{rss=$2;if(rss>0)printf "%8d kB %s\n",rss,name}'

       │
       ▼
同段 RSS 持续增长？→ 内存泄漏，valgrind 排查
同段 RSS 稳定？→ 正常，mlockall 锁定在 RAM
```

## 5. 常用命令速查

```bash
# === CPU ===
top -H -p $(pidof stark_periph_manager_node)         # 线程 CPU 视图
cat /proc/<TID>/status | grep -E "State|voluntary|nonvoluntary|wchan"  # 线程状态
timeout 2 strace -p <TID> 2>&1 | head -20            # 抓系统调用
strace -p <TID> -c & sleep 3; kill %1                # 统计系统调用分布

# === 内存 ===
cat /proc/<PID>/status | grep -E "Vm|Rss|Threads"    # 内存总览 (第一站)
size <binary>                                         # 二进制各段大小
cat /proc/<PID>/smaps | grep -E "^[0-9a-f]|Rss|Pss"  # 各区段详情
while true; do cat /proc/<PID>/status|grep VmRSS; sleep 10; done  # 泄漏监控
ls -lh /dev/shm/stark_shm                            # 共享内存

# === 外设 ===
ls -l /proc/<PID>/fd/                                 # 进程所有 fd
cat /proc/<PID>/fdinfo/<N>                           # 单个 fd 详情

# === 线程 ===
ls /proc/<PID>/task/                                  # 所有线程 ID
for tid in $(ls /proc/<PID>/task/); do echo -n "$tid "; cat /proc/$tid/comm; done  # 线程名

# === 二进制分析 ===
readelf -h <binary>                                   # 架构信息
readelf -S <binary> | grep -E "\.text|\.data|\.bss"   # 段大小
nm --size-sort <binary> | tail -20                    # 最大的符号
```
