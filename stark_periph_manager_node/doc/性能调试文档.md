# stark_periph_manager_node 性能调试文档

> 2026-08-07 | 基于足压传感器串口线程 CPU 100% 排查案例

---

## 1. CPU 占用分析

### 1.1 确认进程

```bash
# 查看系统整体 CPU
top

# 查看指定进程
top -p $(pidof stark_periph_manager_node)

# 或者用 ps 看瞬时值
ps aux | grep stark_periph_manager_node
```

### 1.2 展开线程定位

`top` 里按 `H`，或在命令行直接展开线程视图：

```bash
top -H -p $(pidof stark_periph_manager_node)
```

输出示例（足压串口空转案例）：

```
PID   USER   PR  NI    VIRT    RES   %CPU  S  COMMAND
 711  root  -86   0  231.3m 101.9m   2.0  S  stark_periph_ma   ← RT 线程, 正常
 827  root  -51   0  231.3m 101.9m   4.0  D  stark_periph_ma   ← RT, 阻塞在 I/O
 828  root   20   0  231.3m 101.9m  99.9  R  stark_periph_ma   ← ❌ 异常
 833  root  -91   0  231.3m 101.9m   0.7  S  stark_rt          ← RT 线程, 正常
```

**判断标准**：

| 指标 | 正常 | 异常 |
|------|------|------|
| PR 负数 (RT) | CPU 可能高 (1KHz 循环) | 需结合 S 状态判断 |
| PR=20 (普通) | CPU < 5% | CPU > 50% 大概率空转 |
| S 状态 | S(睡眠) / D(阻塞I/O) | **R(运行中)** |
| PR=20 + CPU 99% + State=R | — | **死循环确认** |

### 1.3 确认线程是否阻塞

```bash
cat /proc/<TID>/status
```

关注四个字段：

```
State:  R (running)                     ← R = 一直在跑
voluntary_ctxt_switches:  0             ← 从未主动让出 CPU
nonvoluntary_ctxt_switches: 780800      ← 被强制切走 78 万次
wchan:  0                               ← 不在内核态阻塞
```

**`voluntary_ctxt_switches = 0` 是死刑判决**——这个线程的循环里没有任何 `sleep/read/wait/select/poll`，纯用户态死循环。

### 1.4 strace 抓系统调用

```bash
# 2 秒快照
timeout 2 strace -p <TID> 2>&1 | head -20

# 统计用
strace -p <TID> -c &
sleep 3
kill %1
```

输出示例：

```
read(8, 0x7fabf23748, 256) = -1 EAGAIN (Resource temporarily unavailable)
read(8, 0x7fabf23748, 256) = -1 EAGAIN
read(8, 0x7fabf23748, 256) = -1 EAGAIN
... (无限重复同一个调用)
```

**读到什么破什么案**：
- `read(8, ..., 256)` → fd=8，buffer 256 字节 → 搜代码 `tmp[256]` + `read` 命中 `FootPressureSensor`
- `EAGAIN` → 非阻塞读，没数据，没 sleep → 死循环

### 1.5 查 fd 确认设备

```bash
ls -l /proc/<PID>/fd/8
```

输出：`8 -> /dev/ttyS7` → 确认是足压串口。

### 1.6 线程名识别

```bash
for tid in $(ls /proc/<PID>/task/); do
    echo "TID=$tid comm=$(cat /proc/$tid/comm)"
done
```

注意：`/proc/comm` 被内核截断为 15 字节，`stark_periph_manager_node` → `stark_periph_ma`。

### 1.7 排查流程图

```
top -H -p <PID>
       │
       ▼
找到 PR=20 + CPU 99% 的 TID
       │
       ▼
cat /proc/TID/status → voluntary_ctxt_switches == 0 ?
       │ 是
       ▼
strace -p TID → 看到死循环调什么
       │
       ▼
ls -l /proc/PID/fd/N → 确认外设
       │
       ▼
搜源码 → 定位代码 → 修复
```

## 2. 常见死循环模式与修复

### 2.1 O_NONBLOCK + continue

```c
// 错：非阻塞读失败不 sleep
m_fd = open(dev, O_RDWR | O_NONBLOCK);
while (running) {
    n = read(m_fd, buf, size);
    if (n < 0 && errno == EAGAIN) continue;  // 空转
}
```

**修复**：读之前去掉 O_NONBLOCK。

```c
m_fd = open(dev, O_RDWR | O_NONBLOCK);
tcsetattr(m_fd, ...);
fcntl(m_fd, F_SETFL, fcntl(m_fd, F_GETFL) & ~O_NONBLOCK);  // 恢复阻塞
```

### 2.2 select/poll 超时后不 sleep

```c
struct timeval tv = {0, 0};  // 超时 0，立刻返回
select(fd+1, &rfds, NULL, NULL, &tv);
// 什么都没做，重新循环
```

**修复**：给合理的超时值。

### 2.3 CAN socket 读空转

```c
n = read(can_fd, &frame, sizeof(frame));
if (n <= 0) continue;  // 没数据就空转
```

**修复**：用 `select` 或 `poll` 等待。

## 3. 内存分析

### 3.1 进程内存总览

```bash
cat /proc/<PID>/status | grep -E "Vm|Rss|Threads"
```

输出示例：

```
VmPeak:   261124 kB      # 虚拟内存峰值
VmSize:   236868 kB      # 虚拟内存当前值
VmRSS:    104372 kB      # 物理内存 (驻留集)
RssAnon:   99064 kB      # 匿名页 (堆/栈)
RssFile:    5244 kB      # 文件映射页 (.so 等)
RssShmem:     64 kB      # 共享内存 (/dev/shm/stark_shm)
Threads:       13        # 线程数
```

### 3.2 共享内存

```bash
ls -lh /dev/shm/stark_shm
```

### 3.3 各区段分布

```bash
cat /proc/<PID>/smaps | grep -E "^[0-9a-f]|Rss|Pss|Name" | head -40
```

### 3.4 线程栈占用

```bash
# 每个线程的栈大小
for tid in $(ls /proc/<PID>/task/); do
    echo -n "$tid: VmStk="
    cat /proc/$tid/status | grep VmStk
done
```

### 3.5 常见内存判断

| 指标 | 正常 | 需关注 |
|------|------|------|
| VmRSS | < 50MB | > 100MB（本案例 104MB 偏高） |
| RssAnon >> RssFile | 正常 | 但 Anon 过大说明堆/栈多 |
| RssShmem | 64KB | > 64KB 说明可能多块 SHM |
| Threads | < 10 | > 15（每个线程默认栈 8MB 虚拟内存） |

本案例 104MB RSS 主要来源：
- `boost` 头文件（header-only 编译膨胀）
- `crow_all.h`（WebServer 单头文件，数十万行）
- 13 个线程的栈开销

## 4. 常用命令速查

```bash
# CPU
top -H -p $(pidof stark_periph_manager_node)        # 线程 CPU
cat /proc/<TID>/status | grep voluntary              # 主动让出次数
timeout 2 strace -p <TID> 2>&1 | head -20            # 系统调用

# 内存
cat /proc/<PID>/status | grep Vm                      # 内存总览
cat /proc/<PID>/smaps | grep -E "Rss|Pss|^[0-9a-f]"  # 各区段详情
ls -lh /dev/shm/stark_shm                            # 共享内存

# 外设
ls -l /proc/<PID>/fd/                                # 进程所有 fd
cat /proc/<PID>/fdinfo/<N>                           # 单个 fd 详情

# 线程
ls /proc/<PID>/task/                                  # 所有线程
for tid in $(ls /proc/<PID>/task/); do cat /proc/$tid/comm; done  # 线程名
```
